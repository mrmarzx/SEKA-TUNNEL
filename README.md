**پنل تانل حرفه‌ای لینوکس**

## پروتکل GAAF – توضیح کامل مکانیزم‌ها

**GAAF** = **G**uarded **A**daptive **A**uthenticated **F**orwarding

### ۱. هدف طراحی

GAAF یک پروتکل تانل اختصاصی است که برای شرایط شبکه محدود (مثل فیلترینگ) طراحی شده و هر دو حالت زیر را پشتیبانی می‌کند:

| حالت     | توضیح                                      | چه کسی اتصال را شروع می‌کند |
|----------|---------------------------------------------|-------------------------------|
| Direct   | ایران به سرور خارج وصل می‌شود               | سرور ایران                    |
| Reverse  | سرور خارج به ایران وصل می‌شود (پیشنهادی)    | سرور خارج (Kharej)            |

### ۲. لایه‌های امنیتی

```
┌─────────────────────────────────────────────┐
│                 Application                 │
├─────────────────────────────────────────────┤
│              GAAF Session Layer             │
│  • Anti-Replay Window (64-bit)              │
│  • Length-hiding Padding (0-255 bytes)      │
├─────────────────────────────────────────────┤
│              AEAD (SM4-GCM)                 │
│  • Confidentiality + Integrity + Auth       │
├─────────────────────────────────────────────┤
│           Key Exchange (X25519)             │
│  • Ephemeral / Static keys + HKDF-SHA256    │
├─────────────────────────────────────────────┤
│                  UDP                        │
└─────────────────────────────────────────────┘
```

#### ۲.۱ تبادل کلید (Key Exchange)
- الگوریتم: **X25519** (Curve25519)
- هر طرف یک جفت کلید دارد (Private / Public)
- با استفاده از **HKDF-SHA256** از shared secret، کلیدهای رمزنگاری و احراز هویت استخراج می‌شود
- امکان چرخش کلید نشست (Session Key Rotation) در طراحی دیده شده

#### ۲.۲ رمزنگاری تأییدشده (AEAD)
- الگوریتم: **SM4-GCM**
  - SM4 → استاندارد ملی چین (GM/T 0002-2012)
  - حالت GCM → Authenticated Encryption with Associated Data
- اندازه کلید: ۱۲۸ بیت
- Nonce: ۹۶ بیت
- تگ احراز هویت: ۱۲۸ بیت
- همزمان محرمانگی + یکپارچگی + احراز هویت را فراهم می‌کند

#### ۲.۳ ضد بازپخش (Anti-Replay)
- پنجره لغزان ۶۴ بیتی
- هر بسته یک شمارنده یکتا دارد
- بسته‌های تکراری یا خیلی قدیمی رد می‌شوند

#### ۲.۴ پنهان‌سازی طول (Length Hiding)
- بعد از ciphertext یک بایت `pad_len` و سپس ۰ تا ۲۵۵ بایت داده تصادفی اضافه می‌شود
- تحلیل‌گر ترافیک نمی‌تواند به راحتی اندازه واقعی payload را تشخیص دهد

### ۳. ساختار منطقی بسته

```
[ header 2B ][ nonce 12B ][ ciphertext + 16B tag ][ pad_len 1B ][ random padding ]
```

- `header`: نسخه پروتکل + فلگ‌ها
- `nonce`: مقدار یکتا برای SM4-GCM
- `ciphertext + tag`: داده رمزشده + تگ احراز
- `pad_len + padding`: پنهان‌سازی طول

### ۴. حالت‌های Direct و Reverse

**Reverse (پیشنهادی):**
- سرور خارج به ایران متصل می‌شود
- نیازی به IP ثابت سمت خارج نیست
- پشت NAT به خوبی کار می‌کند
- با Persistent Keepalive زنده می‌ماند

**Direct:**
- سرور ایران به IP:Port سرور خارج متصل می‌شود
- مناسب وقتی سرور خارج IP ثابت و پورت باز دارد

### ۵. وضعیت فعلی پیاده‌سازی (v1.5.1)

| بخش                        | وضعیت      | توضیح |
|---------------------------|------------|-------|
| مشخصات پروتکل             | کامل       | مستند شده |
| تولید کلید و کانفیگ       | کامل       | در `lib/gaaf.sh` |
| مدیریت متادیتا و lifecycle| کامل       | prepare / start / stop / delete |
| هوک‌های Direct/Reverse    | کامل       | آماده اتصال به پنل |
| مسیر اجرایی پایدار        | فعال       | WireGuard سخت‌شده + متادیتای GAAF |
| موتور کامل SM4-GCM        | برنامه‌ریزی‌شده | نسخه بعدی (باینری gaafd) |

### ۶. نحوه استفاده از GAAF در پنل

1. منوی اصلی → ساخت تانل جدید
2. جهت را انتخاب کنید (Reverse یا Direct)
3. در بخش Transport گزینه **GAAF** را انتخاب کنید
4. پنل به صورت خودکار:
   - جفت کلید می‌سازد
   - فایل کانفیگ و متادیتا می‌نویسد
   - تانل را در وضعیت running قرار می‌دهد

همچنین از منوی اختصاصی GAAF (در صورت اضافه شدن به منوی اصلی) می‌توانید وضعیت و مدیریت دستی انجام دهید.
